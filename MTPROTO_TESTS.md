# Isolated MTProto tests

These diagnostics do not replace the running forwarding bot or change its database.
They log in as the existing bot, not a personal account.

## Required credentials

Create an application at https://my.telegram.org/apps using your developer account.
Save its api_id (number) and api_hash (string) as additional properties in config.json.
They identify the application. Authentication to the bot still uses bot_token.
Do not share the token, hash, or generated .session file.

## Tests

1. Confirm authenticated identity is a bot and resolve the testing supergroup.
2. Send five labelled diagnostic messages, spaced more than three seconds apart.
3. Read them in a single channels.getMessages request.
4. Read modest ranges of older IDs, without storing or printing user content.
5. Delete two of the diagnostic messages; verify empty placeholders and surviving controls.
6. Listen for deletion events and record request-to-event latency for the bot's own deletions.
7. Run a short, conservatively paced read loop. A human must send and delete a message during this interval to verify deletion-event delivery for another sender.
8. Clean up only the diagnostic messages generated by this test.

The bot's own deletion events do not establish that it receives deletions by other members.
An explicit empty result is a candidate, not proof that a human deleted the message.
Unreturned IDs, permission errors, and network failures are not deletions.
Any FloodWait stops the test; this is not a stress test or a search for the server's breaking point.

Install Telethon 1.45.0 in an isolated environment. Usage:

```
python mtproto_probe.py --config config.json --output mtproto-test-results.json --listen-seconds 60 --poll-seconds 2
```

The report excludes credentials and message contents. The session file grants bot access and must stay private.
